- 网站域名：
- 网站名称：

网站必须具有长期扩展能力，而不是一次性生成几十个静态页面后就无法维护。

# 一、单站三大独立内容体系

这是全站最重要的架构原则。

**一个域名，三个职责清晰的内容体系，一个统一的 SEO / GEO 技术底座。**

## 体系 A：知识教程与流量获取

核心目标：覆盖信息型和问题型搜索意图，吸引 Google / Bing 自然搜索流量。

内容包括：

- 机场基础知识
- VPN 基础知识与选择方法
- 代理客户端介绍
- Clash Verge Rev 使用教程
- Clash Meta 使用教程
- v2rayN 安装及使用
- Shadowrocket 使用教程
- Mihomo 配置说明
- sing-box 使用教程
- 各平台客户端安装
- 机场订阅导入教程
- TUN 模式说明
- DNS 设置与故障解决
- 分流规则与策略组
- AI 工具访问问题
- 流媒体地区限制说明
- 线路、协议和节点知识
- 网络连接异常排查

教程必须帮助读者完成具体任务。

一篇教程只围绕一个主要问题展开，包含适用平台、前提条件、操作步骤、常见错误、解决方法及相关教程。

教程体系中的商业推荐必须自然、适度，不得让产品广告覆盖真正需要的操作内容。

## 体系 B：品牌评测与决策支持

核心目标：承接用户的品牌搜索、比较搜索和购买前调研需求。

内容包括：

- 机场品牌数据库
- 单品牌深度测评
- 品牌真实使用场景分析
- 品牌之间的对比
- 套餐价值比较
- 线路与节点分析
- AI / 流媒体适用性
- 客户端兼容性
- 运营与风险信息
- 不同预算的品牌选择指南

每篇评测必须独立研究、独立组织章节、明确证据来源。

不能用同一个文章模板简单替换品牌名称，批量制造没有信息增量的内容。

## 体系 C：商业专题与注册转化

核心目标：帮助已经形成购买意向的用户做决定，并完成注册。

内容包括：

- 机场推荐专题
- 机场排行榜
- 稳定机场推荐
- 靠谱机场推荐
- 便宜机场推荐
- 性价比机场推荐
- 月付机场推荐
- 不限时机场推荐
- 按预算选择机场
- 按使用场景选择机场
- 品牌套餐选择页
- 品牌优惠信息
- 品牌替代方案
- 品牌注册引导

商业页面必须具有明确的比较标准、适用条件和自然 CTA。

推广优先级与客观评测结果要分开管理。商业合作或主推品牌可以在明确标识的推荐位展示，但不能把商业排序伪装成独立实测排名。

### 三套体系的内部关系

知识教程负责发现问题与获取流量。

品牌评测负责提供证据、分析差异与帮助决策。

商业专题负责套餐选择与注册转化。

三套体系分别拥有明确的页面类型、URL、模板和内容要求，同时通过自然内链互相关联。

避免多个页面抢占相同搜索意图。

# 二、技术框架与项目环境

## 2.1 指定技术组合

采用：

**Astro + Tailwind CSS + Markdown / MDX + Content Collections + Pagefind + Sitemap + RSS + Apache 静态部署。**

技术要求：

1. Astro 使用静态输出模式 `output: "static"`。
2. Tailwind CSS 负责样式，避免复杂 UI 框架。
3. Markdown 作为主要内容格式，MDX 用于需要特殊组件的页面。
4. 使用 Astro Content Collections 和 Schema 校验内容。
5. Pagefind 实现全站静态全文搜索。
6. 使用自动 Sitemap、robots.txt 和 RSS。
7. 使用 `astro:assets` 优化本地图片。
8. 使用 TypeScript 管理品牌、价格、关键词和配置数据。
9. Apache 直接托管静态 HTML。
10. 仅在必要交互中使用少量客户端 JavaScript。

不安装与项目目标无关的大型 CMS、数据库服务、可视化编辑器或沉重的前端组件库。

没有真实需求时，不引入 SSR、复杂 API、用户登录系统或额外后台。

# 四、完整 SEO 信息架构

采用：

**一级导航 → 二级专题 → 三级内容集群 → 深度文章 → 品牌评测 → 商业转化。**

每个一级栏目必须具备独立专题首页。

每个二级栏目应当拥有自己的搜索意图、关键词组、核心说明、内容索引和 FAQ。

每个三级内容集群围绕一个清晰的用户任务组织多篇文章。

### 每个一级栏目需要建立

1. 一级专题首页。
2. 二级分类与真实专题页面。
3. 核心 Pillar 内容。
4. 相关 Cluster 文章。
5. 问题型 FAQ 页面或章节。
6. 相关品牌评测入口。
7. 相关教程入口。
8. 关联专题与自然内链。

对重要主题，规划 2–3 个有实质差异的三级集群，每个集群可规划 6–15 个独立搜索意图的标题。

文章数量是规划容量而非凑数目标。

没有足够内容的主题先建立完整大纲和任务记录，不将重复或空白页面直接发布。

### URL 规则

- 教程：`/tutorials/{topic}/{slug}/`
- 客户端：`/clients/{client}/`
- 品牌库：`/brands/`
- 品牌详情：`/brands/{brand-slug}/`
- 品牌评测：`/reviews/{brand-slug}/`
- 品牌对比：`/compare/{slug}/`
- 价格专题：`/pricing/{slug}/`
- 综合推荐：`/jichang/{slug}/`
- 故障排查：`/troubleshooting/{slug}/`
- 风险专题：`/risks/{slug}/`

路径只是一套默认方案。

如果现有 URL 已有有效内容或搜索表现，不要随意变更。

如确需调整路径，生成旧 URL 到新 URL 的明确 301 重定向映射，并落实到 Apache。

# 五、建立持续发现关键词的系统

这是网站未来持续增长的核心功能。

不要仅提供一份静态关键词列表。

必须建立一个可以不断导入新关键词、去重、聚类、分析、分配 URL、生成选题任务并记录表现的轻量级关键词系统。

## 5.1 初始核心关键词

覆盖以下主题。

机场推荐类：

机场推荐、机场排行、靠谱机场、稳定机场、好用的机场、2026 机场推荐、性价比机场、机场导航。

价格类：

便宜机场、一元机场、一分机场、月付机场、年付机场、不限时机场、低价机场、套餐价格。

品牌类：

品牌名+评测、品牌名+官网、品牌名+套餐、品牌名+优惠码、品牌名+替代品、品牌名+使用教程。

VPN 类：

VPN 推荐、免费 VPN、手机 VPN、安卓 VPN、VPN 软件评测、游戏加速器。

客户端类：

Clash Verge Rev、Clash Meta、Clash、v2rayN、Shadowrocket、Mihomo、sing-box、客户端安装、订阅导入。

AI 类：

ChatGPT 机场、Claude 机场、Gemini 机场、AI 工具访问、Netflix 解锁、YouTube 加速。

线路类：

故障类：

节点超时、订阅失败、DNS 错误、无法连接、订阅更新失败、TUN 模式异常。

风险类：

机场跑路、机场安全、机场避坑、退款、机场替代。

## 5.2 长尾关键词拓展

针对每个核心关键词，按以下维度扩展：

- 时间：2026、2027、最新版本等。
- 价格：免费、低价、10 元以内、20 元以内、月付、年付。
- 设备：Windows、macOS、Android、iPhone、Linux。
- 地区：香港、日本、新加坡、美国等。
- 使用场景：办公、AI、视频、游戏、远程协作。
- 需求：推荐、教程、比较、下载、安装、配置、故障。
- 用户阶段：新手、进阶、技术用户。
- 疑问形式：是什么、怎么用、哪个好、为什么、如何解决、是否值得购买。

建立长尾关键词组合规则，但不得仅靠机械排列就认定存在真实搜索需求。

## 5.3 关键词发现数据源

设计可扩展的输入系统，支持：

- Google Search Console 导出数据
- Bing Webmaster Tools 导出数据
- Google Trends
- 搜索建议词
- 相关搜索
- 用户真实问题
- 站内 Pagefind 搜索词
- 已有文章标题
- 已有品牌资料
- 客户端官方文档
- 竞争内容的公开主题结构
- 合法获取的外部关键词研究数据

优先使用用户上传的 CSV、JSON、TXT 和已有数据文件。

尚未连接第三方平台时，使用本地导入机制，不得伪造搜索量、点击量、展示量或竞争难度。

未知指标必须保留为空值或标注未获得数据，不能自动写入伪造数字。

## 5.5 搜索意图分类

至少区分：

**Informational**

用户主要想理解概念、学习操作或解决问题。

**Commercial Investigation**

用户正在调查品牌、评测、差异和适用场景。

**Transactional**

用户正在查找套餐、优惠、价格、注册方式和购买入口。

**Navigational**

用户正在寻找某个品牌、软件或官方网站。

**Troubleshooting**

用户正在排查客户端或连接异常。

每个关键词应当拥有一个最主要的搜索意图。

## 5.6 关键词自动聚类

根据语义、搜索意图、实体和用户需求进行分组。

要求：

- 同意图关键词尽量映射到同一主页面。
- 不同需求可以使用独立页面。
- 不同页面避免目标关键词互抢。
- 一个主关键词对应一个主要目标 URL。
- 同一关键词允许成为其他页面的自然次级词。
- 识别没有目标页面的内容缺口。
- 识别多个页面竞争同一意图的情况。

生成：

`keyword-map.csv`

`keyword-clusters.json`

`content-opportunities.csv`

`keyword-cannibalization-report.md`

## 5.7 自动优先级评分

建立可解释的关键词优先级模型。

参考指标：

- 搜索需求信号
- 商业转化价值
- 内容缺口
- 已有排名机会
- 竞争强度
- 品牌相关性
- 页面建设成本
- 内容更新价值

没有真实指标时，允许使用标记为“编辑判断”的定性评分，但不能展示成已验证的搜索量。

输出 P0、P1、P2、P3 优先级。

优先建设核心流量页、商业决策页和能够完善内部链接关系的支撑内容。

## 5.8 持续更新机制

建立可执行脚本，实现：

```text
导入关键词
    ↓
标准化与去重
    ↓
搜索意图分类
    ↓
语义聚类
    ↓
匹配现有 URL
    ↓
发现内容缺口
    ↓
生成内容任务
    ↓
更新关键词映射表
    ↓
输出优化报告
```

建议每周更新关键词机会，每月分析关键词表现与专题覆盖情况。

采用本地脚本或可选 CI 调度实现，不依赖静态 Apache 服务器自动运行后台任务。

没有真实搜索数据时，系统仍能完成关键词整理、内容规划和缺口识别。

# 七、单品牌万字级深度评测矩阵

这是内容建设的重点任务。

**每个唯一品牌建立一篇独立、结构完整、目标为万字级深度的中文评测文章。**

每篇品牌评测以约 10000 中文字级别的深入内容作为长期建设目标。

重点是独立信息增量、真实分析和用户决策价值，而不是通过重复段落机械凑字数。

当资料不足以支撑可信的万字内容时，先完成有依据的内容与详细待补充计划，标记为未完成，不得虚构评测来填满篇幅。

## 7.1 每篇品牌评测至少覆盖

1. 核心结论与适合人群
2. 品牌基本信息
3. 运营历史及资料可信度
4. 价格与套餐体系
5. 月付、年付及一次性流量包区别
6. 套餐实际成本分析
7. 流量倍率与性价比
8. 节点地区及线路覆盖
9. IEPL、IPLC 或其他线路信息
10. 协议与客户端兼容性
11. Windows、macOS、Android、iOS 使用方式
12. 实际测速数据分析
13. 延迟、速度与测试条件
14. 晚高峰稳定性
15. ChatGPT、Claude、Gemini 使用场景
16. Netflix、YouTube 等流媒体表现
17. 适合与不适合的人群
18. 品牌优势
19. 品牌限制与潜在风险
20. 同类产品比较
21. 常见使用故障
22. 售后、支付和退款资料
23. 套餐选择建议
24. 相关教程和对比入口
25. FAQ 问答
26. 数据来源与更新时间
27. 结论及透明注册 CTA

以上是内容覆盖范围，不要求每篇文章都使用完全相同的章节排序。

必须根据各品牌实际卖点、资料完整度和用户搜索需求设计差异化结构。

## 7.2 品牌内容差异化

文章不能只是：

“某某机场速度快、节点多、价格便宜、值得推荐。”

必须具体回答：

- 它真正适合什么人？
- 它在哪些方面具有优势？
- 哪些条件下并不适合？
- 它与相似价格品牌有什么不同？
- 哪些信息来自品牌宣传？
- 哪些有第三方或独立测试证据？
- 哪些信息仍需核实？
- 哪个套餐符合特定用户的实际需求？

同类品牌必须给出真实、可解释的比较依据。

## 7.3 套餐价格模块

每个有足够套餐资料的品牌，设计 4–5 个主要套餐层级的重点展示模块。

如果资料存在更多套餐，提供完整价格表。

如果某品牌实际只有少量可确认套餐，不得凭空补足数量。

每个套餐字段：

- 套餐名称
- 价格
- 计费周期
- 月流量或总流量
- 流量重置规则
- 线路倍率
- 设备限制
- 适合人群
- 优惠码
- 价格核实时间
- 注册入口

价格卡片需要清楚区分：

月付价格、年付总价、年付折算月价、永久流量包一次性付款金额。

## 7.4 批量内容生成策略

分批建设，不因为单次生成长度限制就牺牲质量。

按以下顺序执行：

1. 提取全部品牌基础数据。
2. 完成唯一品牌去重。
3. 建立全部品牌详情页。
4. 为每个品牌创建独立关键词映射。
5. 为每个品牌创建深度评测大纲。
6. 优先完成光速云详细评测。
7. 逐批完成其他品牌评测。
8. 对每篇文章执行内容质量检查。
9. 更新内部链接和专题页。
10. 记录完成状态与缺失资料。

生成 `reports/brand-review-progress.md`，记录每个品牌的内容字数、证据状态、已完成章节、待补充任务及发布状态。

不要把仅有大纲的文章标记为已完成万字测评。

# 十、SEO 技术规范

所有可索引页面必须满足统一技术标准。

## 10.1 页面 Meta

每个页面生成：

- 唯一 Title
- Meta Description
- 唯一 H1
- Canonical
- Robots
- Open Graph
- Twitter / 社交分享信息
- 发布时间
- 更新日期
- 面包屑
- 必要的语言与页面类型信息

Title 必须优先准确描述搜索意图，而不是机械堆积多个关键词。

## 10.2 Schema 结构化数据

按实际页面类型使用：

- Organization
- WebSite
- BreadcrumbList
- Article / BlogPosting
- ItemList
- SoftwareApplication
- HowTo（适用时）
- FAQPage（适用时）

结构化数据必须与页面实际可见内容一致。

不要为了搜索结果特殊展示而滥用 Schema。

## 10.3 Sitemap

使用自动生成 Sitemap。

只包含允许索引的有效页面。

草稿、测试页、无实际内容的占位页不能进入正式索引清单。

## 10.4 页面性能

优化：

- LCP
- CLS
- INP
- 图片体积
- CSS 体积
- 字体加载
- 静态页面 HTML
- 移动端导航
- 搜索交互
- 图片懒加载
- JavaScript 使用量

默认优先静态 HTML 和服务器可直接读取的正文。

## 10.5 Apache 部署

生成适用于静态项目的 Apache 配置。

包括：

- 正确的静态路径访问
- 自定义 404
- 需要时的 301 重定向
- 压缩支持
- 合理缓存策略
- 静态资源访问规则
- Canonical 与 URL 规范一致性

不得依赖仅适用于 Cloudflare Pages 或 Vercel 的部署机制。

## 10.6 域名尚未确定

统一设置：

`siteConfig.name`

`siteConfig.siteUrl`

`siteConfig.description`

`siteConfig.branding`

域名未配置时应能完成本地开发和构建，但不得把测试域名作为正式公开站点的 Canonical 提交索引。

提供上线前必填配置检查。

# 十一、AI 搜索优先：GEO / AEO 深度优化

网站架构和内容必须充分考虑机器解析、语义检索和 AI 问答引用。

目标是增加被发现、理解、采纳和引用的机会，不承诺任何平台排名。

## 11.1 Answer-First 写作策略

每篇文章在开头设置直接回答。

例如用户搜索：

“机场节点超时怎么办？”

页面开头首先解释常见原因、推荐检查顺序和适用条件。

不要先写大量与问题无关的行业背景。

重要章节均优先回答对应小问题。

## 11.2 实体信息结构

每篇文章建立：

核心实体 → 相关概念 → 技术参数 → 适用场景 → 比较依据 → 常见问题。

对重要实体保持名称、定义、属性和引用的一致性。

## 11.3 GEO 内容模块

重要文章尽量拥有：

- 简短定义
- 核心答案
- 关键事实
- 条件化结论
- 对比表
- 操作步骤
- 数据来源
- 常见问题
- 更新时间
- 相关主题

确保独立段落也能被正确理解。

## 11.4 精确量化数据

价格、流量、延迟、速度、节点数量、折扣、设备数量等指标必须明确：

- 单位
- 时间
- 条件
- 来源
- 数据类型
- 最近更新日期

不得混淆 Mbps 与 MB/s。

不得将年付折算价格写成真实月付价格。

不得把品牌宣传数字描述为自己完成的测试。

## 11.5 主题权威性

通过完整的专题覆盖、统一术语定义、原创比较、真实证据和合理内部链接建设主题关联。

不要以所谓“实体密度”“AI 关键词密度”作为主要优化指标。

## 11.6 AI 可检索性

- 内容不应依赖 JavaScript 才能显示。
- 正文必须存在于静态 HTML。
- 标题层级清晰。
- 表格使用语义化结构。
- 图片有描述。
- 页面具有稳定 URL。
- 重要答案不应隐藏在无法解析的交互区域。
- 适用时提供清晰的作者、资料来源和更新信息。

# 十三、内部链接矩阵与转化路径

必须建立结构化的内链管理方案。

核心关系：

**教程文章 → 相关品牌评测 → 相关套餐 → 注册入口**

**机场推荐专题 → 品牌详情 → 深度评测 → 套餐选择**

**品牌评测 → 同类品牌对比 → 最终选择**

**客户端文章 → 订阅教程 → 故障排查 → 相关品牌资料**

**风险专题 → 避坑知识 → 替代品牌比较**

## 13.1 内链策略

按照用户的真实下一步需求添加链接。

每篇重点文章应链接到其 Pillar 主题、相关文章及必要的品牌或对比页面。

不要求所有文章机械地放置相同数量的内链。

## 13.2 防止关键词互抢

每个主要搜索意图应有明确的目标页面。

例如：

- “光速云评测”优先匹配光速云深度评测。
- “光速云价格”可以由品牌详情或独立价格页承担，取决于内容深度。
- “便宜机场推荐”优先匹配对应商业专题。
- “Clash Verge Rev 安装”优先匹配独立客户端教程。

避免一个品牌同时生成多个内容几乎相同的 URL。

## 13.3 转化追踪

在不影响用户隐私和加载性能的前提下，预留：

- CTA 点击事件
- 推广品牌
- 来源页面
- 内容类型
- 推荐模块
- 目标注册 URL

可以接入现有统计平台，或以轻量配置预留统计接口。

没有真实统计数据时，不展示虚构的转化效果。

# 十四、建立可持续内容更新机制

网站不仅要能够发布文章，还要知道下一步该更新什么。

建立内容状态管理：

```text
idea
planned
researching
draft
review
published
needs-update
archived
```

每篇文章记录：

- 目标关键词
- 目标搜索意图
- 所属专题
- 主实体
- 内容类型
- 来源资料
- 创建时间
- 最近更新
- 下一次检查日期
- 相关品牌
- 转化目标
- 内容负责人或作者

## 14.1 定期更新分类

高频更新：

价格、优惠码、客户端版本、服务状态、节点测试。

中频更新：

品牌评测、排名、对比、使用场景推荐。

低频更新：

基础概念、技术原理、通用知识。

更新周期可以依据数据变化而调整，不应仅靠日期自动修改文章而不更新实际内容。

## 14.2 数据更新流程

```text
发现新信息
     ↓
检查来源
     ↓
确认品牌或内容实体
     ↓
比较现有版本
     ↓
更新数据文件
     ↓
更新关联页面
     ↓
检查内链与 Schema
     ↓
重新构建网站
     ↓
输出更新日志
```

价格、优惠和品牌运营信息不能仅凭时间推断，需要实际来源确认。

## 14.3 内容质量审计

定期检查：

- 重复关键词
- 重复标题
- 内容过薄
- 文章结构过度相似
- 失效内链
- 失效外部链接
- 未更新的价格
- 缺失品牌资料
- 不完整的教程
- 不匹配的结构化数据
- 图片缺失
- URL 冲突

形成报告并按优先级处理。
