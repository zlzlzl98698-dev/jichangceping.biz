## 一、项目任务

你现在是一名资深中文 SEO 内容架构师、GEO/AEO 优化专家、VitePress 工程师、搜索意图研究专家、技术内容编辑和网站信息架构师。

请直接读取当前 VitePress 项目，对网站现有 10 个一级导航下面的全部二级专题进行审计、分类、扩展、内容重构和页面级 SEO/GEO 优化。

本次任务重点是：

**将二级专题从普通分类入口升级为独立的、可被搜索引擎收录、有完整正文、能解决细分用户需求的专业 SEO Topic Hub（主题中心页）。**

这不是重新建设网站，也不是重复一级专题的工作。

整体内容逻辑：

一级专题负责核心大词与主题总览。

二级专题负责细分搜索需求、中长尾关键词与专题决策。

三级文章负责具体问题、深度教程、实际评测和长尾搜索。

品牌商业页面负责套餐详情、注册入口和转化。

形成：

**一级专题 → 二级专题 → 三级文章集群 → 品牌评测 / 比较 → 商业详情与转化。**

### 核心目标

1. 完成 10 大一级主题下全部二级专题的审计和建设。
2. 每个二级专题拥有独立的核心关键词和搜索意图。

4. 扩展相关长尾关键词、问题词、比较词和场景词。
5. 将现有三级文章准确归入对应二级专题。
6. 建立二级专题之间的知识关联。
7. 实现从一级专题到二级专题，再到三级内容的有效内链。
8. 为具备商业意图的主题添加真实的品牌评测和套餐入口。
9. 统一完善 Google/Bing SEO 和 GEO/AEO。
10. 保证所有正式发布的专题都有实际内容并可正常访问。

# 二、修改范围与保护原则

本次只允许升级：

- 已有二级专题页面。
- 缺失且确有独立搜索需求的二级专题页面。
- 二级专题专用组件。
- 二级专题专用数据文件。
- 对应的关键词映射及内链配置。
- 本次专题的 SEO 元数据。
- 专题所需的局部样式。

不得：

- 重新设计网站首页。
- 重新开发整个 VitePress 框架。
- 无故改动现有一级导航。
- 批量重写一级专题正文。
- 批量重写已有三级文章。
- 重建品牌数据库。
- 更换整体网站设计系统。
- 随意改变已收录页面 URL。
- 创建大量无正文的空白 SEO 页面。
- 删除原有有价值的内容及有效链接。

如果需要其他页面新增回链，只记录在内链建议报告中，不自动越界修改。

必须保留现有 URL、有效内容、可靠来源和原有有价值的锚点。

一级主题负责综合机场选择。

二级专题负责不同用户需求和推荐条件。

核心关键词：

- 线路及设备兼容情况

- 排名依据与数据日期
- 不同场景下的选择差异
- 详细品牌评测链接

不能将商业置顶顺序冒充客观性能排行。

核心关键词：

靠谱机场、靠谱机场推荐、机场是否靠谱。

运营状态、价格透明度、技术信息、客服、退款、长期套餐风险和资料核实方法。

内容重点：

### 01.4 好用的机场

核心关键词：

好用的机场、新手机场、容易使用的机场。

客户端易用性、安装难度、设备兼容、售后支持、套餐理解难度和新手选择。

新手机场推荐、机场新手入门、适合新手的机场。

### 01.6 高性价比机场

性价比机场、性价比高的机场、实惠机场推荐。

实际付款、流量成本、倍率、设备限制、线路价值及不同预算选择。

重点：系统版本、权限、依赖、配置和日志。

### 09.6 连接成功但无法访问

关键词：

代理连接成功没网络、节点已连接但网页打不开。

重点：系统代理、DNS、分流、TUN 和服务端访问限制。

### 09.7 速度慢与延迟高

关键词：

机场速度慢、节点延迟高、代理网速慢。

重点：带宽、线路拥塞、测试环境、节点选择。

### 09.8 系统代理冲突

关键词：

系统代理冲突、代理设置异常、关闭代理后没网络。

重点：操作系统设置、客户端退出状态及恢复方法。

# 五、二级专题深度正文标准

## 5.1 内容长度

每个独立二级专题首页以 **5,000—8,000 个有效中文汉字** 为常规深度编辑目标。

对搜索需求广、技术复杂、证据充分的核心二级专题，可扩展至 8,000—12,000 字。

所有字数均指具有实际价值的正文，不包括导航、代码、通用卡片、页脚和重复内容。

资料不足时不强行凑字数。

不允许通过重复解释、关键词堆砌或批量生成相似段落完成目标。

## 5.2 每个页面必须具备的内容能力

每个二级专题应当能够独立回答其核心搜索问题。

根据实际搜索意图合理组合：

1. 专题 H1 与核心问题。
2. Answer-First 简明结论。
3. 用户需求与适用范围。
4. 主题概念和必要背景。
5. 关键比较、操作或判断方法。
6. 实际条件与限制。
7. 真实的数据、示例或测试。
8. 选择建议或行动步骤。
9. 常见错误与误区。
10. 专业 FAQ。
11. 相关三级文章。
12. 上级专题和相关二级专题。
13. 相关品牌评测或商业入口（适用时）。
14. 来源、核实日期及更新时间。

这不是固定的 14 个 H2 模板，应根据每个主题的搜索意图调整顺序和结构。

## 5.3 二级专题首页不能退化为文章目录

二级专题不是把十几篇文章标题堆在一起。

页面本身必须有：

- 足够完整的解释。
- 用户能立即获得的答案。
- 关键比较或实际步骤。
- 明确的限制和条件。
- 延伸阅读的选择依据。

三级文章负责深入展开某个具体问题，而不是代替二级专题回答主要问题。

# 六、三级文章集群映射

## 6.1 为每个二级专题规划三级内容

每个二级专题建立 2—4 个不同搜索需求的三级集群。

每个三级集群规划 6—12 个可执行的文章选题。

文章选题必须具体，不能只是简单替换品牌名或关键词。

每篇三级文章规划包括：

- 文章标题
- 核心关键词
- 长尾关键词
- 搜索意图
- 用户任务
- 目标读者
- 所属二级专题
- 建议 URL
- 正文核心问题
- 主要 H2 结构
- 参考来源需求
- 上级专题链接
- 相关内容链接
- 是否需要品牌转化
- 优先级
- 内容完成状态

### 示例：节点超时二级专题

三级内容可分：

**A. 根据客户端排查**

- Clash Verge 节点全部超时怎么办？
- v2rayN 节点测试超时的常见原因
- Shadowrocket 节点超时排查指南
- Android 客户端连接超时怎么办？

**B. 根据故障原因排查**

- DNS 异常为什么会导致节点超时？
- 订阅更新成功但节点仍然超时怎么办？
- 所有节点突然无法连接如何定位？
- 端口连接失败与订阅失效有什么区别？

**C. 根据使用场景排查**

- 手机热点可以连接但 Wi-Fi 无法连接怎么办？
- Windows 系统代理开启后没有网络怎么办？
- 晚高峰节点连接失败如何检查？
- 更换网络后节点无法使用如何处理？

通过这样的结构建立真实问题集群，而不是简单增加相似标题。

## 6.2 三级文章只规划，不越界批量重写

本次重点完成二级专题。

已有三级文章优先识别、分类和建立内链。

尚不存在的三级文章生成待办清单。

不要将只有标题的空白页面发布到 Sitemap。

三级文章的深度扩写留给下一阶段单独执行。

# 七、二级专题之间的关键词边界

## 7.1 防止关键词互相竞争

建立统一关键词主页面归属表。

例如：

- “机场推荐”归一级综合推荐页面。
- “稳定机场”归独立稳定机场二级专题。
- “月付机场”归价格与套餐下的月付专题。
- “Clash Verge Rev”归客户端软件专题。
- “Clash Verge 订阅导入失败”归相关具体排障文章。

如果两个页面覆盖的用户任务基本相同，优先判断是否应该合并。

不要为了创建更多页面而重复建立相同意图的 URL。

## 7.2 二级专题与三级文章边界

二级专题覆盖某一类完整问题。

三级文章解决这个问题下的具体子任务。

例如：

二级专题“Clash Verge Rev”负责：

- 软件是什么。
- 适合什么用户。
- 支持哪些系统。
- 基础功能。
- 主要安装流程。
- 常见使用问题。
- 相关教程入口。

三级文章分别负责：

- Windows 详细安装教程。
- macOS 安装教程。
- 如何导入订阅。
- TUN 模式配置。
- 分流规则设置。
- 启动失败排查。

二级专题不需要机械重复六篇三级教程的全部正文。

# 八、内部链接体系

## 8.1 每个二级专题必须有明确上下游

建立：

一级专题 → 二级专题 → 三级文章。

二级专题 → 相关二级专题。

二级专题 → 相关品牌评测。

二级专题 → 相关套餐或商业详情。

三级文章尚未完成时，不得创建空链接。

## 8.2 内链必须有真实用途

例如：

- 稳定机场 → IEPL 线路说明。
- 月付机场 → 套餐价格比较。
- ChatGPT 机场 → AI 兼容性测试。
- Clash Verge → 订阅导入教程。
- 节点超时 → DNS 故障排查。
- 机场跑路 → 退款和替代方案。

锚文本应当描述目标页面的实际用途。

不机械地在所有二级专题底部重复大量相同链接。

# 九、二级专题 SEO 优化

## 9.1 每个页面独立配置

必须包含：

- 唯一 Title
- 唯一 Meta Description
- 唯一 H1
- 明确的主关键词
- 自然的相关长尾词
- 合理 H2/H3 结构
- Canonical
- Breadcrumb
- 静态 HTML 正文
- 有效内链
- 真实更新时间
- 图片 alt
- 适用的 JSON-LD

## 9.2 搜索引擎友好

确保：

- 页面不是空分类。
- 正文可以在构建后的 HTML 中直接读取。
- 内容具有独立搜索价值。
- URL 稳定。
- 不存在重复 Title。
- 不存在多个互相竞争的同意图页面。
- Sitemap 只收录实际完成的可索引页面。
- 不对搜索引擎和普通用户展示不同正文。

## 9.3 GEO/AEO

采用：

**问题 → 直接答案 → 条件说明 → 证据 → 比较或步骤 → 结论 → 延伸阅读。**

为重要知识点提供清晰定义、实体关系和可独立理解的答案。

涉及价格、线路、性能、软件版本及服务状态时，标注可核实的来源和日期。

不承诺被 ChatGPT、Gemini、Perplexity 或 Google AI Overviews 引用。

# 十、二级专题视觉升级

## 10.1 页面视觉定位

继承当前 VitePress 品牌化简白主题。

保持一级专题与二级专题视觉统一，但二级专题应当具有更明确的细分主题特征。

推荐使用：

- 专题 Hero
- 简明答案区
- 主题目录
- 关键知识卡片
- 对比表
- 操作流程
- 常见问题
- 三级文章卡片
- 相关专题
- 相关推荐
- 合理的 CTA

不同二级专题使用符合实际搜索需求的组件。

例如：

价格专题重点用套餐比较表。

客户端专题重点用系统兼容矩阵。

线路专题重点用技术图解。

排障专题重点用故障诊断流程。

风险专题重点用风险核实清单和事件时间线。

不能把全部二级专题设计成完全相同的品牌卡片页面。

## 10.2 移动端

检查 375px、768px 及桌面宽度。

保证：

- 目录可用。
- 表格不会造成整页横向溢出。
- 正文字体清晰。
- 长文章具备合理章节层次。
- 按钮不重叠。
- 图片适配屏幕。
- 重要内容不依赖复杂 JavaScript 才能显示。

# 十一、品牌资料与商业转化

## 11.1 复用现有品牌数据

涉及机场推荐、价格、品牌、AI 和线路的二级专题时，使用项目中的真实品牌数据库。

不能硬编码大量重复品牌数据。

同一品牌的：

- 名称
- 套餐
- 优惠码
- 线路
- 客户端
- 注册链接
- 测试资料

必须保持来源一致。

## 11.2 合理的 CTA

按页面类型区分：

- 推荐专题：查看深度评测。
- 价格专题：查看套餐详情。
- 品牌专题：查看品牌资料。
- 客户端专题：阅读安装教程。
- AI 专题：查看兼容性测试。
- 技术专题：查看实际测试说明。
- 排障专题：进入解决步骤。
- 风险专题：了解替代方案。

付费推广链接必须有清晰披露。

使用：

`target="_blank" rel="nofollow sponsored noopener"`

不因商业推广而编造价格、排名或测速结果。

# 十三、验收标准

## 13.1 结构检查

- 10 大一级主题结构完整。
- 全部实际二级专题已建立映射。
- 每个正式发布的二级专题都有真实页面。
- 不存在重复路由。
- 不存在孤立的重要专题。
- 不存在空链接。
- 不存在只有标题的空白 SEO 页面。

## 13.2 内容检查

- 每个二级专题拥有独立搜索意图。
- 每页具有完整、有价值的正文。
- 页面开头直接回答主要问题。
- 三级文章有明确归属。
- 关键词分配不冲突。
- 没有批量换词正文。
- 比较、参数和风险说明具有依据。
- 缺失数据清楚标记。

## 13.3 SEO/GEO 检查

- Title 与 H1 正确。
- Meta Description 与页面一致。
- Canonical 正确。
- HTML 可直接读取主要正文。
- 面包屑正确。
- JSON-LD 与可见内容一致。
- Sitemap 不包含空白草稿。
- 页面内链有效。
- 相关实体名称一致。
- 重要数据标注来源和日期。

## 13.4 技术检查

- VitePress 构建通过。
- 移动端布局正常。
- 表格可读。
- 页面无明显溢出。
- 目录与锚点可用。
- 品牌数据正常读取。
- 原有一级专题和网站首页功能不受影响。

# 十五、最终执行要求

本次项目的核心定位：

**一级专题负责争取核心主题搜索流量。**

**品牌评测负责用户选择。**

**商业详情页负责套餐与注册转化。**

不批量重写一级专题和三级文章。

现在开始：

**读取当前项目 → 识别二级专题 → 建立关键词边界 → 审计正文 → 深度扩展 → 组织三级内容集群 → 建立内链 → 完善 SEO/GEO → 验证构建 → 交付实际修改结果。**

最终把全部二级专题建设成能够持续覆盖细分搜索需求、支撑三级长尾内容、形成主题权威性并自然承接品牌转化的专业内容矩阵。
