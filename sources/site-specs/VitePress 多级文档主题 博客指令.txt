### 资料处理原则

首先建立数据审计结果：

- 合并重复品牌，处理品牌别名。

## 三、技术框架与工程架构

采用轻量、稳定、易维护的静态技术方案。

### 基础技术

- VitePress：静态站点框架。
- Vue 3：交互组件。
- TypeScript：配置、数据结构和校验。
- Markdown：教程、评测和长篇文章内容。

- 少量自定义 Vue 组件：商业页面、品牌库、价格比较、测试图表。

# 四、最重要的架构：一个域名、三个内容体系

三个内容体系相互独立，但共享导航、数据、搜索、SEO、GEO 和设计系统。

## 体系 A：教程与问题解决中心

**职责：获取信息型与问题型搜索流量。**

主要覆盖：

- 软件下载安装。
- Windows、macOS、Linux 客户端。
- Android、iPhone、iPad 客户端。
- Clash Verge Rev 配置。
- Clash Meta / Mihomo 配置。
- v2rayN、v2rayNG、Shadowrocket。
- sing-box 和 Hiddify。
- 机场订阅导入。
- 分流规则与策略组。
- TUN 模式。
- DNS 设置。
- 节点超时。
- 无法连接。
- 订阅更新失败。
- 客户端运行错误。
- AI 工具连接问题。

教程必须优先解决实际问题，而不是在教程开头直接推销品牌。

标准教程结构：

问题或任务 → 直接答案 → 适用系统和版本 → 操作前准备 → 分步骤教程 → 截图说明 → 常见错误 → 排查方法 → FAQ → 延伸阅读。

教程页面允许在合适位置推荐相关服务，但不得干扰教程主体。

每篇教程需要覆盖一个明确任务，不得创建大量只更换软件名称和关键词的重复文章。

## 体系 B：评测、对比与选择中心

**职责：承接商业调查类搜索，帮助用户做选择。**

主要覆盖：

- 机场推荐。
- 机场排行。
- 性价比机场。
- 稳定机场。
- 便宜机场。
- 专线机场。
- 品牌独立测评。
- 品牌之间的对比。
- 不同价位机场比较。
- 节点与线路分析。
- 套餐和流量分析。
- AI 与流媒体兼容性。
- 客户端兼容能力。
- 风险与售后比较。

标准评测结构：

核心结论 → 品牌介绍 → 真实套餐 → 价格与流量 → 节点与线路 → 客户端兼容 → 测试数据 → AI/流媒体 → 优点 → 局限 → 适合人群 → 同类对比 → FAQ → 注册入口。

评测需要提供具体的比较依据，不得只是品牌宣传语的重复。

## 体系 C：商业转化中心

**职责：承接品牌词、购买词、价格词和注册意图。**

主要覆盖：

- 品牌详情。
- 品牌官网入口说明。
- 品牌注册指南。
- 套餐与价格。
- 优惠码与活动。
- 不同需求的套餐选择。
- 新用户使用流程。
- 服务常见问题。
- 相关替代品牌。

商业页面要让用户能够快速找到：

1. 这是什么品牌。
2. 主要提供什么。
3. 当前资料记录的套餐和价格。
4. 各套餐有什么区别。
5. 适合什么用户。
6. 如何注册或购买。
7. 使用前有哪些注意事项。

商业页面需要清楚标识推广关系，不能伪装成完全无商业利益的独立推荐。

### 三个体系的关系

教程 → 相关选择指南 → 评测 → 品牌详情 → 注册

推荐专题 → 评测 → 品牌详情 → 套餐 → 注册

故障文章 → 解决方案 → 必要时介绍替代服务

品牌搜索 → 品牌详情 → 价格与优惠 → 注册

三个体系可以互相推荐，但必须按用户实际需求建立链接，不要每篇文章机械加入大量 CTA。

年份关键词必须通过配置或内容规划数据统一维护，不能在跨年后继续机械保留过时标题。

## 3. 按搜索意图分类

建立以下 Intent：

- Informational：知识说明
- Navigational：导航查找
- Commercial：比较与选择
- Transactional：购买与注册
- Troubleshooting：故障解决

一个关键词必须明确对应主要搜索需求，不允许所有页面都用“推荐排行榜”的方式回答。

## 4. 主题集群

每个核心主题建立：

Pillar Page → Cluster Pages → Supporting Articles → Commercial Pages。

例如：

Clash Verge Rev 专题

- Clash Verge Rev 是什么
- Clash Verge Rev 下载
- Windows 安装教程
- macOS 安装教程
- 订阅导入
- TUN 模式
- 规则分流
- 无法连接
- 更新失败
- 常见错误
- 兼容的服务选择指南

## 5. 关键词优先级机制

根据以下维度计算内容机会：

- 搜索需求
- 搜索意图匹配度
- 商业价值
- 现有内容缺口
- 可提供的信息增量
- 网站已有搜索曝光
- 内容制作与维护成本

建立可调整的评分权重，生成内容优先级队列。

不要凭空生成月搜索量，也不要直接宣称某词“低竞争、高流量”。

预留以下数据来源：

- Google Search Console 导出数据
- Bing Webmaster Tools 导出数据
- 关键词工具 CSV 数据
- 现有网站页面清单
- 已发布文章数据库
- 可获得的站内转化事件统计

优先实现 CSV 导入、去重、归一化、内容机会评分和报告输出。

在没有 API 密钥的情况下仍可使用本地脚本运行。

支持周期性重新导入数据并执行：

- 发现新关键词
- 找出已有曝光但排名低的页面
- 找出高曝光低点击页面
- 找出同一查询对应多个页面的情况
- 检测过时价格和版本
- 生成待更新内容列表
- 生成新文章建议

Apache 静态服务器不负责后台定时任务。定期执行应使用构建机、CI 或明确配置的调度环境，不能假装纯静态站点已经具备后台自动监控能力。

## 7. 关键词互抢控制

同一搜索意图优先由一个主页面承接。

建立关键词与 URL 映射，检查：

- 标题重复
- H1 重复
- 内容高度相似
- 同关键词多页面互相竞争
- 不必要的年份页
- 近义词拆分过细
- 品牌页面与专题页面定位冲突

输出 Keyword Cannibalization 检查报告。

# 八、每一家品牌制作独立深度评测

每个不同品牌必须具备独立的品牌详情页与深度评测页。

示例：

- `/brands/guangsu/`
- `/reviews/guangsu-review/`

品牌详情页承接品牌识别、官网、套餐和注册意图。

评测页承接品牌评测、使用体验、线路和优缺点等搜索意图。

两个页面必须提供不同的信息价值，不能重复同一篇文章再更换标题。

### 万字级内容矩阵

深度评测的规划目标为约 8,000–12,000 汉字，并根据资料丰富度和搜索需求安排内容。

对于数据充分的品牌，优先完成万字级深度内容。

对于资料不足的品牌，不允许编造数据或使用重复废话强行凑到一万字。应优先完成真实有效的分析，附带待补充资料清单，并将后续扩展列入内容队列。

### 深度评测建议章节

1. 评测摘要与核心结论
2. 品牌背景与运营信息
3. 品牌定位与主要特色
4. 真实套餐及价格
5. 不同套餐如何选择
6. 线路与协议分析
7. 节点地区及覆盖情况
8. 节点延迟与带宽测试
9. 晚高峰表现（有相应测试才展示）
10. ChatGPT、Claude、Gemini 使用情况
11. Netflix、YouTube 等流媒体支持情况
12. Windows 与 macOS 客户端
13. Android 与 iOS 客户端
14. 安装与订阅使用说明
15. 使用中常见问题
16. 服务优点
17. 服务限制
18. 适合人群
19. 不适合人群
20. 和相关品牌的差异
21. 退款、付款及使用风险
22. 常见问题 FAQ
23. 评测方法与信息来源
24. 最近更新时间
25. 注册及套餐选择入口

以上是内容覆盖维度，而非要求每个品牌采用一模一样的文章目录。

不同品牌必须根据实际卖点与数据调整结构和论证重点。

### 套餐模块

资料充足时，展示至少 4–5 个具有代表性的不同套餐层级，并提供完整套餐查看能力。

如果某品牌确实只有少量有依据的套餐，则如实展示，不允许为满足数量要求编造产品。

支持：

- 价格卡片
- 月付与年付切换
- 套餐比较表
- GB 与价格计算
- 不限时套餐说明
- 优惠码提示
- 套餐选择建议
- 注册 CTA

套餐卡片要突出真实差异，不要让所有套餐呈现完全相同的卖点。

### 品牌文章内容差异化

每篇测评均需包含独有的信息增量。

不同品牌的重点可以是：

- 自研客户端体验
- 第三方客户端兼容性
- 入门价格
- 高流量套餐
- 不限时套餐
- 专线线路
- 覆盖区域
- 支持的应用场景
- 客户服务
- 测试结果
- 价格限制和风险

禁止批量只修改品牌名、套餐数字、标题和优惠码生成模板化内容。

# 十、SEO 页面基础设施

从网站初始化开始实现 SEO，而不是后期补丁式增加。

### 全站 SEO

- 唯一 Title
- 唯一 Meta Description
- 每页一个主要 H1
- 合理 H2/H3
- Canonical

- 社交分享图

- 真实更新时间

- Organization
- WebSite
- BreadcrumbList
- Article
- BlogPosting
- ItemList
- SoftwareApplication（适用时）
- HowTo（适用时）
- FAQPage（适用时）

Schema 必须与页面真实可见内容一致。

不要为获得富结果资格而编造评分、评论、购买价格或 FAQ。

没有证据时不输出 AggregateRating。

# 十一、GEO / AEO：AI 搜索内容架构

全站以机器易于理解和用户易于获取答案为目标。

采用 Answer-First 写作方式。

### 每页知识结构

核心实体 → 基础定义 → 相关概念 → 技术参数 → 适用场景 → 比较依据 → 独立答案 → 常见问题。

### 核心规范

每篇文章应明确：

- 核心问题是什么。
- 最直接的回答是什么。
- 回答适用于什么条件。
- 哪些信息已验证。
- 数据来自哪里。
- 什么时候测试或更新。
- 哪些结论仍有不确定性。
- 用户下一步应该做什么。

### FAQ 体系

FAQ 不是简单堆砌问题。

每个 FAQ 需包含：

- 明确的问题。
- 可独立理解的简短答案。
- 必要的前提条件。
- 相关解释。
- 相关页面链接。

FAQ 必须和正文内容保持一致。

### 实体关联

为以下实体建立清晰的语义联系：

品牌、客户端、操作系统、协议、线路、节点地区、价格、套餐、AI 服务、流媒体、故障类型。

例如：

光速云 → VLESS → 客户端兼容 → 套餐价格 → 节点覆盖 → 适用场景 → 品牌评测。

每个实体应该有稳定名称、必要别名和相关页面。

避免将同一个实体在不同页面写成互相矛盾的介绍。

### AI 易引用内容

重要章节尽可能提供：

- 简短定义
- 明确结论
- 参数表
- 比较表
- 条件判断
- 数据来源
- 更新日期
- 问答摘要

不能保证任何 AI 搜索平台一定收录、采纳或引用本站。

# 十二、全站内链矩阵

建立自动化、可检测的内链体系。

推荐路径：

教程 → 客户端专题 → 兼容服务选择指南

机场推荐 → 价格比较 → 品牌评测

品牌评测 → 同类品牌比较 → 品牌详情

线路教程 → 线路对比 → 相关服务

故障排查 → 修复教程 → 必要时的替代方案

风险信息 → 品牌状态 → 替代选择

### 内链规则

- 使用描述性锚文本。
- 同一语义不要重复堆砌链接。
- 不要所有文章都指向同一个商业页面。
- 优先按用户下一步任务推荐。
- 重要专题和核心内容应具备清晰的导航路径。
- 避免孤立文章。
- 自动检测失效链接。

开发内链检查脚本，输出：

- 孤立页面
- 死链
- 重复目标
- 缺失反向关联
- 不符合内容体系的商业链接
- 关键词定位冲突

# 十三、商业转化系统

建立统一的商业转化组件：

- BrandCTA
- PricingCTA
- CouponBox
- CompareCTA
- RecommendedBrand
- RelatedAlternatives
- AffiliateDisclosure

### 注册链接

以项目内品牌清单和品牌专用资料为主要来源。

注册链接不允许分散硬编码。

必须集中在 `data/links.ts` 或等价的数据文件中管理。

所有推广链接使用：

`target="_blank" rel="nofollow sponsored noopener"`

在适当位置明确提示存在推广合作关系。

### CTA 放置

根据页面类型选择不同转化位置。

教程页：完成教程后的相关选择指南。

评测页：核心结论后、套餐区、文章结尾。

品牌页：品牌介绍、套餐选择、注册流程。

比较页：比较结果、具体品牌详情。

避免全站强制弹窗、虚构倒计时、伪造销量、虚假用户评价。

预留可接入分析系统的事件：

- article_view
- brand_detail_view
- review_view
- pricing_view
- affiliate_click
- coupon_click
- compare_view

事件不应收集不必要的个人敏感信息。

在正式配置统计平台前，不要虚构转化量、注册数量或收入数据。

# 十四、视觉设计与用户体验

虽然底层采用 VitePress，但最终成品不能像未经设计的默认开发文档网站。

设计方向：

**专业知识库 + 内容型评测平台 + 品牌数据库 + 商业服务比较站。**

### 网站整体

- 主体使用简洁、专业的白色或浅色背景。
- 强调清晰排版与阅读体验。
- 适当使用深色技术图表。
- 色彩不要过度霓虹化。
- 卡片和按钮采用一致的设计语言。
- 文章页面强调阅读。
- 品牌页面强调信息比较。
- 商业页面强调套餐与选择。

### 首页结构

首页不是大量链接的集合。

应包含：

1. 品牌化 Hero。
2. 网站主要价值说明。
3. 搜索入口。
4. 十大专题入口。
5. 核心推荐内容。
6. 品牌精选区。
7. 最新评测。
8. 热门客户端教程。
9. 故障解决入口。
10. 价格与套餐专题。
11. 风险与信息核实说明。
12. 最近更新文章。
13. 完整页脚。

首页应像高质量的专业博客和内容门户，而不是传统软件文档目录。

### 文章页

- 结论先行。
- 清晰标题。
- 文章摘要。
- 阅读目录。
- 重要信息表格。
- 多步骤教程。
- 响应式图片。
- 相关内容。
- 返回上级专题。
- 更新日期。
- 适当的商业入口。

### 移动端

重点适配：

360px、390px、768px、1280px、1440px 等典型宽度。

十大导航不能在移动端强行挤成一排。

桌面端可采用紧凑导航和多列下拉菜单；移动端采用分级折叠菜单。

保证按钮尺寸、文章宽度、表格横向滚动、图片显示和目录交互合理。

全站用户可见文字默认使用简体中文，技术产品名称保留原文。

# 十六、Apache 静态部署

网站必须能够构建成静态文件并部署到 Apache。

实现并验证：

- 正确的构建输出目录。
- HTTPS 环境下的绝对 URL。
- Apache DirectoryIndex。
- cleanUrls 路径映射。
- 正确的静态文件类型。
- 图片、CSS、JS 缓存策略。
- 404 错误处理。
- sitemap.xml。
- robots.txt。
- 不错误地将所有不存在的 URL 返回首页。

# 十八、具体执行顺序

按以下阶段实施，但最终交付必须是实际项目，而不是只有阶段规划。

### 阶段一：项目审计

读取全部文件，整理品牌、关键词、图片、价格、链接及现有 URL。

### 阶段二：基础框架

搭建 VitePress、主题、全局布局、首页、导航、页脚、搜索、SEO 配置和基础路由。

确保可以构建。

### 阶段三：10 大专题

建立 10 个一级专题及真实二级栏目，创建内容入口与内链关系。

### 阶段四：品牌数据库

导入去重后的全部品牌，生成结构化数据、品牌库、详情页、价格组件和品牌筛选功能。

### 阶段五：深度品牌评测

针对全部品牌分批撰写独立深度内容。

优先处理资料丰富、搜索意图明确和商业价值较高的品牌。

不得因为批量处理困难就将其余品牌自动省略。

### 阶段六：教程和知识库

根据第三方客户端资料和关键词矩阵，建立软件下载、安装配置、故障排查和网络知识内容。

### 阶段七：数据图表

使用现有真实图片和测试资料，实现测速、解锁、线路及品牌技术图表组件。

### 阶段八：持续关键词系统

实现关键词数据库、扩展规则、搜索数据导入、关键词分组、机会评分、内容更新队列和重复页面检查。

### 阶段九：SEO/GEO/AEO

完善每个页面的 Title、Description、结构化数据、实体关联、内链、答案优先段落及 Sitemap。

### 阶段十：测试与部署

完成构建、链接检查、页面检查、移动端检查、静态部署验证。

对于尚未完成的内容，明确记录实际完成状态与阻碍，不允许把只有大纲的品牌页宣称为已完成万字评测。
