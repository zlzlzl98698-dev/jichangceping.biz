faq:
  - q: 节点测试全部显示 Timeout（超时），是不是机场一定跑路了？
    a: 绝大部分“突然全部 Timeout”首先源自本地或账户状态问题，按发生概率依次为：1）套餐到期或月流量耗尽；2）电脑或路由器本地系统时间偏差超过 30–60 秒导致 TLS/证书校验失败；3）机场更换了中转入口 IP 而本地长期未更新订阅；4）本地宽带 DNS 无法解析节点域名。应先走完四步基础自查，再判断是否为服务端大面积故障。

    a: 最常见原因是代理客户端未正常退出（如直接强杀进程或断电关机），导致 Windows/macOS 系统设置里的“系统代理（127.0.0.1:7890）”没有自动清除，浏览器仍在把请求发向已经关闭的本地端口。到系统网络设置里手动关闭局域网代理开关，或重新打开再正常关闭一次客户端即可恢复。
  - q: 为什么手机用 5G 流量能连上节点，一连家里 Wi-Fi 就全部超时？
    a: 这说明机场节点本身在线，问题定位在家庭宽带或路由器侧。常见原因包括：宽带光猫/路由器开启了过度激进的安全防火墙、运营商宽带本地 DNS 污染了入口域名、家庭宽带 IPv6 抢占未通的路由，或路由器上残留了失效的透明代理规则。
  - q: 为什么我在机场官网找不到订阅链接，或者导入第三方客户端一直报格式错误？
    a: 请先核对该品牌是否属于仅限专属客户端模式（如飞猫云、隐形人、无忧链接、Firefly、灵猫网络、SOGO 云、闪跃、全球云）。这类品牌不提供通用订阅，只能使用其官方客户端登录；若确认支持通用订阅仍报格式错误，则通常是把 V2Ray Base64 链接误导入了仅接受 YAML 的客户端，或客户端内核过旧不支持 AnyTLS / Hysteria 2 等新协议。

# 机场连接故障诊断与网络排障中心

当代理突然“连不上”、“更新不了订阅”或者“一开代理连国内网都断了”时，最忌讳的做法是**在未定位层级前胡乱修改十几个高级开关、反复卸载重装客户端，甚至匆忙再去买一家新机场**。

网络代理链路由 **账户与订阅层 → 本地系统与客户端内核层 → 本地 ISP 宽带与 DNS 层 → 机场中转与落地节点层** 串联而成。本排障中心完全从纯技术诊断出发，提供一套可在 **3 分钟内锁定故障层级** 的标准化决策流程。

## 一、三分钟快速定位：故障现象分流表

请先对照你当前屏幕上看到的报错信息或网络表现，直接跳转到对应象限执行排障：

| 故障现象分类 | 典型报错关键字 / 症状表现 | 高频根因 Top 3 | 专项排障入口 |
| :--- | :--- | :--- | :--- |
| **A. 订阅拉取与解析失败** | `Network Error`、`TLS handshake timeout`、`YAML syntax error`、`403/404`、导入后节点数为 0 | 1. 订阅域名被本地宽带 DNS 污染或阻断<br>2. 开了失效的系统代理导致“死锁更新”<br>3. 订阅格式与客户端内核不匹配 / 误选专属客户端机场 | [订阅失败与更新报错排查](/troubleshooting/subscription-failed/) |
| **B. 节点全部 Timeout / 有延迟没网速** | `Timeout`、`io: read/write on closed pipe`、`connection reset`、延迟有数字但网页转圈打不开 | 1. **系统时间不同步**（误差 > 30 秒致 TLS 失败）<br>2. 账户流量耗尽 / 套餐到期 / 在线设备数超限<br>3. 长期未更新订阅，旧中转入口已下线或被 UDP QoS | [节点超时与全部不可用排查](/troubleshooting/node-timeout/) |
| **C. TUN 启动失败 / 国内断网 / DNS 污染** | 终端不通、开启 TUN 后全网瘫痪、关闭软件后国内网页打不开、AI/流媒体提示所在地区不支持 | 1. Windows 未装 Service Mode 权限或与网游加速器/公司 VPN 抢路由<br>2. 异常退出残留系统代理 `127.0.0.1` 或残留 `198.18.x.x` Fake-IP 缓存<br>3. IPv6 泄漏或分流规则置为 Global / Direct 误选 | [TUN 异常与 DNS 污染排查](/troubleshooting/tun-dns-error/) |
| **D. 特定服务（ChatGPT/Netflix）被拒** | 速度正常、Google 能开，唯独 ChatGPT 报 `Access Denied` 或 YouTube 变成送中、Netflix 仅自制剧 | 1. 当前节点出口 IP 被目标平台风控（如香港节点访问 OpenAI）<br>2. 浏览器残留定位 Cookie 或 WebRTC 暴露真实 IP<br>3. 分流策略组把该域名误判进了直连或不兼容地区 | 切换美/新/日原生节点并参考 [AI 与流媒体中心](/ai-streaming/) |

## 二、通用“五步黄金自检法”（适用于 80% 突发断连）

在深入修改任何复杂参数前，请按顺序做完这 5 个动作，每一项耗时不超过 30 秒：

### 第 1 步：确认“关掉代理后，本地原网是否正常”
- 先在客户端中关闭“系统代理”和“TUN 模式”，彻底退出客户端。
- 打开浏览器访问一个纯国内站点（如 `baidu.com` 或 `qq.com`）。
  - **如果关掉客户端后国内网站也打不开**：说明系统网络设置残留了 `127.0.0.1:端口` 代理，或本地路由器/宽带本身断网。Windows 请进入 `设置 -> 网络和 Internet -> 代理`，关闭“使用代理服务器”；macOS 进入 `系统设置 -> 网络 -> Wi-Fi 详细信息 -> 代理`，取消勾选网页代理与安全网页代理。

### 第 2 步：校准操作系统时间（极易被忽略的头号杀手）
- 现代加密协议（`VLESS`、`VMess`、`Trojan`、`Hysteria 2`、`AnyTLS`）普遍依赖严格的 TLS 证书有效期或时间戳校验。新装系统、双系统切换（Windows + Linux 硬件时钟 UTC 冲突）、笔记本电池亏电或软路由重启未连上 NTP 服务器，都会导致系统时间偏差几分钟甚至几小时。
- **操作**：进入系统“日期和时间”设置，点击 **“立即同步”**，确保精确到秒且时区正确（`UTC+8`）。

### 第 3 步：登录机场官网后台核对“三项硬状态”
用手机蜂窝网络（4G/5G，往往比固网宽带更少受本地 DNS 缓存影响）或备用通道打开机场官网用户面板，检查：
1. **剩余流量与到期日**：是否已在当月结算日前跑光了额度（注意看倍率节点，如 2x/3x 高倍率专线会加倍消耗流量）。
2. **官网公告栏**：是否有“入口维护，请立即更新订阅”或“更换备用订阅域名”的通知。
3. **同时在线设备数**：若购买的是限制设备数的套餐，家里软路由 + 手机 + 公司电脑同时挂着，超限后新连接会被服务端静默丢弃。

### 第 4 步：在关闭系统代理的状态下“强制直连更新一次订阅”
很多用户节点已经挂了，却还开着代理开关去点“更新订阅”——客户端试图通过已经失效的节点去访问订阅服务器，必然 100% 失败（即**代理更新死锁**）。
- **操作**：先关掉系统代理与 TUN 开关 → 点击订阅列表旁边的“更新（不通过代理）” → 若主订阅域名超时，去机场官网后台看看是否提供了“备用订阅链接/防失联订阅地址”。

### 第 5 步：用手机热点做“交叉隔离实验”
如果电脑端怎么更新或连接都超时：
- 打开手机个人热点（使用蜂窝流量），让电脑连接手机热点后再测一次订阅更新和节点 URL-Test。
- **若连手机热点立刻恢复正常**：100% 说明机场与你的电脑配置都没坏，问题出在**家庭宽带运营商（ISP DNS 污染 / 省际防火墙策略 / UDP QoS）或家里路由器设置**。此时只需为电脑配置加密 DNS（如阿里 `223.5.5.5` / 腾讯 `119.29.29.29` DoH）或切换其他协议/中转入口节点即可绕开。

## 三、不同设备平台的特有高频坑位

### 1. Windows 平台特有问题
- **与网游加速器 / 企业办公 VPN 冲突**：雷神/UU 等加速器以及公司内网的桑达/深信服 EasyConnect、Cisco AnyConnect 都会修改 Windows 底层 WFP 过滤驱动或路由表。建议遵循“用公司 VPN 时关机场 TUN，用机场 TUN 时彻底退出加速器后台服务”。
- **旧客户端停更导致新协议丢失**：仍在使用停更的 `Clash for Windows` 导入包含 `VLESS`、`Hysteria 2` 或 `AnyTLS` 节点的订阅时，软件会直接报错或跳过全部新协议节点。请升级至 [Clash Verge Rev](/clients/clash-verge-rev/) 或 [FlClash](/clients/flclash/)。

### 2. macOS 平台特有问题
- **系统更新后网络扩展权限失效**：大版本升级 macOS 后，TUN 虚拟网卡或后台 Helper 权限可能被重置，导致开启 TUN 无流量。在客户端设置中重新点击“重装服务模式 / 重新授权”即可。
- **装错芯片架构包**：Apple Silicon 机型运行未装 Rosetta 的 Intel 包或混用旧核心二进制会导致内核启动即崩溃，核对指南见 [macOS 客户端选型](/clients/macos/)。

### 3. Android 与 iOS 平台特有问题
- **国产安卓杀后台**：连接几分钟后状态栏钥匙图标消失，需将应用加入电池优化白名单并锁定后台。
- **iOS 内存超限闪退**：iOS 给 NetworkExtension 进程分配的运行内存非常克制（约 50MB）。若在 Shadowrocket、Stash 或 Quantumult X 中加载了体积庞大的远程去广告规则集，在并发打开大量网页图片或观看高清流媒体时会触发系统强杀重连。精简规则集即可根治。

### 4. OpenWrt 软路由平台特有问题
- **路由器重启后节点全红**：软路由断电重启瞬间尚未完成 WAN 口拨号与 NTP 时间同步，此时透明代理插件已抢先启动，因系统时间停留在过去而导致 TLS 握手全败。等待 NTP 同步完成后手动重启一次插件服务，或在启动脚本中加入时间同步延迟检测。
- **版本与防火墙不兼容**：例如在低于 24.10 的旧版 OpenWrt 上强行安装 [Nikki](/clients/nikki/)，或在缺少 `kmod-nft-tproxy` 的固件上开启 TProxy UDP 转发，都会直接报错无法拦截流量。

## 四、深入排查子手册与应急预案

请根据具体故障点进入对应的深度操作指南：

1. **[订阅失败与更新报错专项排查](/troubleshooting/subscription-failed/)**：逐条解决 `SSL/TLS` 错误、状态码 `403/404/502`、`YAML` 解析报错、User-Agent 拦截与专属客户端误判。
2. **[节点超时与全部不可用专项排查](/troubleshooting/node-timeout/)**：排查时钟偏移、假延迟（ICMP vs TCP/URL-Test）、端口/UDP 限速与服务端入口变更。
3. **[TUN 异常与 DNS 污染专项排查](/troubleshooting/tun-dns-error/)**：修复虚拟网卡驱动失败、`198.18.0.0/15` 残留断网、IPv6 双栈分流异常与局域网互访失灵。
4. **若确认服务端长期失联**：当排除所有本地与宽带原因，且机场官网连续多日无法访问、工单与官方群禁言失联时，请参考 [机场跑路与异常信号识别](/risks/exit-scam-signals/) 与 [品牌替代与平滑迁移指南](/risks/alternatives/)，启用备用方案止损。
